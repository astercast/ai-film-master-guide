Set up the asset registry

Gets you: You will have one named list of every character, place and prop in your film, locked before you generate anything — so shot 40 still matches shot 1.

What this is
Build the named, versioned asset registry before generating shot one.
First step
Create registry.md: one @-tag per asset, one verbatim descriptor each.
You will need
Character list with reference photos; Location list; Prop list; Naming convention: @<char>_<project>_<scene>_v<1>
Time
About 3 minutes for a first run-through (5 steps; estimated from the procedure itself — your model’s generation time is extra).
Level
Beginner — made to be usable on a first project.
Before this
Best after the skill before it on the Path (skill 182 of 241: Plan a microdrama run's economics (Studio 2.5)) — but everything it needs is listed below, and nothing else is assumed.
Proof — the worked example
@mara_ON_neon_v1 — woman, late 20s, copper bob, leather jacket, gold hoop. Face anchor: mara_face_v1.png (locked, never re-run).

Use when

Starting any production longer than ~3 minutes. Nothing shoots until the registry is locked.

Inputs

  • Character list with reference photos
  • Location list
  • Prop list
  • Naming convention: @<char>_<project>_<scene>_v<1>

Procedure

  1. Create registry.md: one @-tag per asset, one verbatim descriptor each.
  2. Character sheets: close-up face anchor first (never re-run the base portrait), then full-body looks.
  3. Locations: bake the lens look and grade into the plate image.
  4. Props: front/rear split sheets for hero props.
  5. State changes get NEW tags (@char_wet) — never overwrite.

Worked example

@mara_ON_neon_v1 — woman, late 20s, copper bob, leather jacket, gold hoop. Face anchor: mara_face_v1.png (locked, never re-run).

API references

  • data/v1/checklists.json

Pitfalls

  • Generating before the registry exists — every later fix costs 10×.
